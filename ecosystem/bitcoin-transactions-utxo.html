Bitcoin Transactions & UTXO

How Bitcoin records transfers of value through transaction inputs, outputs and the Unspent Transaction Output model.

1. What Is a Bitcoin Transaction?

A Bitcoin transaction is a digitally signed data structure that describes how previously created outputs are spent and how new outputs are created.

Unlike a conventional bank transfer, a Bitcoin transaction does not simply subtract an amount from one account and add it to another. It consumes existing unspent transaction outputs and creates new outputs according to the rules of the Bitcoin protocol.

Transactions are broadcast to the peer-to-peer network. Nodes independently check whether they satisfy the applicable consensus rules before accepting them into their view of the network.

2. Inputs and Outputs

A Bitcoin transaction is primarily composed of inputs and outputs.

An input references an output created by an earlier transaction. It also provides the information required to satisfy the spending conditions associated with that output.

An output specifies an amount of bitcoin, denominated in satoshis, and a locking condition that determines how the output may be spent.

A transaction can contain multiple inputs and multiple outputs. This structure allows a wallet to combine previously received outputs and distribute value among several destinations.

3. The UTXO Model

UTXO stands for Unspent Transaction Output. It describes an output from an earlier transaction that has not yet been spent.

The Bitcoin system tracks which transaction outputs remain unspent. These outputs form the set of funds that can be referenced by future transactions.

A wallet's available balance is calculated from the unspent outputs it can control. The balance is therefore not stored as a single account value directly on the blockchain.

Each UTXO has an amount and a spending condition. To use it, a new transaction must reference that specific output and satisfy its conditions.

4. How Bitcoin Transactions Work

Consider a wallet that controls an unspent output worth 1 BTC. Its owner wants to send 0.3 BTC to another person.

The wallet creates a transaction that references the existing output as an input. It then creates an output worth 0.3 BTC for the recipient and, if necessary, another output returning the remaining value to an address controlled by the sender.

The transaction must also account for the network fee. Once signed, it can be broadcast to the network for validation and possible inclusion in a block.

This example illustrates the UTXO process. Actual transactions may use multiple inputs and outputs, and the values depend on the available outputs and the transaction fee.

5. Transaction IDs and Outpoints

A transaction is identified by a transaction ID, commonly called a TXID. It is derived from the transaction's serialized data using the hashing rules defined by Bitcoin.

An individual output is identified by combining the transaction ID with the output's index within that transaction. This reference is called an outpoint.

A future transaction uses the outpoint to identify precisely which earlier output it intends to spend. This allows the network to distinguish between different outputs created by the same transaction.

6. Change Outputs

Bitcoin transactions generally spend entire UTXOs. They do not divide an existing output by simply subtracting a smaller amount from it.

When the value of an input exceeds the amount intended for the recipient and the transaction fee, a wallet may create an additional output called a change output.

The change output returns the remaining value to an address controlled by the sender's wallet. It becomes a new UTXO and can be spent in a future transaction.

Change is not a separate type of Bitcoin protocol transaction. It is an ordinary transaction output that the wallet recognizes as belonging to the sender.

7. Transaction Fees

A Bitcoin transaction fee is the difference between the total value of its inputs and the total value of its outputs.

In simplified form:

Transaction Fee = Total Inputs − Total Outputs

Fees are generally expressed in satoshis per virtual byte (sat/vB). The transaction's virtual size and the fee rate influence the total fee paid.

Users can choose a fee rate when creating a transaction. Miners select transactions for inclusion in blocks, taking account of their expected fee revenue and other relevant considerations.

A higher fee rate can improve a transaction's competitiveness for block inclusion, but it does not guarantee confirmation at a particular time.

8. Digital Signatures and Scripts

Bitcoin uses scripts and cryptographic signatures to define and verify the conditions under which transaction outputs may be spent.

An output contains a locking script, also known as a scriptPubKey. A later transaction provides the required unlocking data or witness information to satisfy those conditions.

Digital signatures demonstrate authorization to spend an output under the rules defined by its spending conditions. They do not reveal the private key itself.

Bitcoin supports different script and signature mechanisms. Their details depend on the output type and the applicable protocol rules.

9. Validation and Double Spending

Before accepting a transaction, Bitcoin nodes independently check its structure and compliance with the consensus rules.

Among other checks, nodes verify that referenced outputs exist, remain unspent, and that the transaction satisfies the conditions required to spend them.

The UTXO model helps prevent double spending: the same output cannot be spent twice in the same valid chain of transactions.

Conflicting transactions may nevertheless be broadcast before confirmation. Nodes and miners must resolve which transaction, if any, becomes part of the accepted blockchain history.

A transaction appearing in a wallet or being relayed by the network does not by itself mean that it has been confirmed in a block.
